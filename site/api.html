API

JSON access to the Zoekt search index. The API is public and read-only; no key is required.

The search backend is Zoekt. The web interface compiles its search fields to the backend query syntax documented below; API callers may use that syntax directly.

POSThttps://formalization-corpus.dzackgarza.com/api/search

Example

curl -s https://formalization-corpus.dzackgarza.com/api/search \
  -H 'Content-Type: application/json' \
  -d '{"Q": "IsometryEquiv", "Opts": {"MaxDocDisplayCount": 5}}'

Print the source and path of each matching file:

curl -s https://formalization-corpus.dzackgarza.com/api/search \
  -H 'Content-Type: application/json' \
  -d '{"Q": "Hasse invariant file:\\.lean$", "Opts": {"MaxDocDisplayCount": 20}}' \
  | jq -r '.Result.Files[] | "\(.Repository)  \(.FileName)"'

Backend query syntax

A bare term is a substring; anything more is a regular expression. Terms combine with a space, or separates alternatives, and - negates.

QueryMeans
Jordan splittingboth substrings, in the same file
spinor (genus or norm)grouping and alternation
theorem\s+\w*Hassea regular expression
repo:mathlib4restrict to indexed sources matching that pattern
repo:^leanprover__hex-lll$one indexed source exactly
file:\.lean$restrict by path — e.g. \.v$ Rocq, \.agda$ Agda, \.thy$ Isabelle, \.miz$ Mizar, \.mm$ Metamath
-file:testexclude paths matching test
case:yescase-sensitive; the default folds case
content:foomatch file contents only, never a path

The raw Repository field is the search index's source identifier, not a reader-facing repository name. For GitHub sources it normally has the form owner__repo; the Sources page maps those identifiers to canonical repository/library names and URLs. Use the identifier with repo: when filtering the raw API.

Options

FieldEffect
MaxDocDisplayCountHow many files to return. Without it you get every match, which for a common term is thousands.
ChunkMatchesReturn matching lines with their positions. Without it a file comes back named but empty.
NumContextLinesLines of context around each match.
WholeReturn each matching file in full, base64 in Files[].Content. A 60-file result runs about 1–2 MB.
MaxMatchDisplayCountCap matches per file.
MaxWallTimeNanoseconds. The server stops early and says so rather than hanging.

Response

{
  "Result": {
    "Files": [
      {
        "Repository": "leanprover-community__mathlib4",
        "FileName": "Mathlib/Analysis/Quaternion.lean",
        "Language": "Lean",
        "ChunkMatches": [
          {
            "Content": "…base64 of the matching lines…",
            "ContentStart": {"ByteOffset": 4213, "LineNumber": 160, "Column": 1},
            "Ranges": [{"Start": {"ByteOffset": 4260, "LineNumber": 160, "Column": 48},
                        "End":   {"ByteOffset": 4273, "LineNumber": 160, "Column": 61}}],
            "FileName": false
          }
        ]
      }
    ],
    "FileCount": 122,
    "MatchCount": 483,
    "FilesConsidered": 129,
    "Duration": 28853571
  }
}

Response details:

  • The counters sit directly in Result. There is no Stats key, though zoekt's Go source names the embedded struct that way. Duration is nanoseconds.
  • Content is base64 of raw bytes. Decode as UTF-8 — this corpus is full of ℍ, ≃ₗᵢ[ℝ] and 𝕜, and a latin-1 decode mangles all of it.
  • Ranges are byte offsets from the start of the file, while Content starts at ContentStart.ByteOffset. Subtract before indexing into the chunk.
  • A chunk with "FileName": true matched the path, not the contents, and its Content is the path.

List indexed sources

curl -s https://formalization-corpus.dzackgarza.com/api/list \
  -H 'Content-Type: application/json' \
  -d '{"Q": "repo:hex"}' \
  | jq -r '.List.Repos[].Repository.Name'

Each entry includes index statistics — document count, content bytes, line counts — under Stats.

Fair use

This runs on one small virtual machine against a multi-gigabyte Zoekt index. Simple repeated queries are usually fast; a broad regular expression across hundreds of indexed sources can take several seconds on the search server. Pass MaxDocDisplayCount, prefer repo: and file: filters over scanning everything, and set MaxWallTime if you are running a loop.

The endpoint sends permissive CORS headers because it is public and read-only. To run the whole index yourself, build from the repository with just sync && just index.

The API searches indexed source files and does not modify upstream repositories.
